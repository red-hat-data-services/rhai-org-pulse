📋 EA/GA Strategy — Phase Distinctions
Early Access (EA1/EA2): Development-focused releases with strict readiness gates. Features can slip to next cycle without customer impact. Model confidence tiers are calibrated for engineering delivery probability.

General Availability (GA): Customer-facing final release with zero tolerance for slips. Strategy shifts to risk minimization. Confidence reflects real-world support impact.

Implications: Features in EA may fail readiness checks and defer; GA items require higher proof points before commit. Model trains separate prediction surfaces per phase using historical delivery rates.

📊 Priority Score — How It's Calculated
The SCORE column comes from org-pulse · modules/releases/server/planning/health/priority-scorer.js. It is a composite 0–100 score computed across all features at export time:
ComponentWeightHow it's computed
RICE score30%Raw RICE normalized to [0,1] relative to min/max across all features in the plan. Missing RICE → median substituted.
Outcome alignment30%0 if not aligned. If aligned: max(0.3, 1.0 − (rank−1)×0.1) — position 1=100, position 2=90 ... position 8+=30.
Target Version25%Current release=100 · next release=60 · release after=20 · unrecognized TV=10 · no TV=0.
Jira Priority15%Blocker=100 · Critical=80 · Major=60 · Normal=40 · Minor=20.
Why this matters for explainability: Score 77 vs 76 is a tiny difference — usually a single Priority Outcome position or one Jira priority tier. Two features with similar scores can have very different delivery risk. The ML confidence score (this tool) adds the missing risk dimension: a feature with Score=77 but 9/17 FPDoR and a prior slip is more likely to miss than one with Score=76, 16/17 FPDoR, and no slips.
Potential improvement — Risk-Adjusted Score: Score × (ML confidence / 100). Score=77, conf=78% → 60. Score=76, conf=84% → 64. Risky features would drop below ready ones in rank. Not yet wired into the sort — confidence is shown separately in the CONFIDENCE column.
About TYPE column: TYPE (DP/TP/GA) is read from the Jira "Release Type" field. If unset, falls back to title prefix — matches both bracket format ([TP] / [DP]) and plain-text prefixes (Tech Preview - / Dev Preview -).

🤖 ML Model — Training & Performance
Model Summary — v6 3.4+3.5 + FPDoR cycles
AlgorithmRandom Forest + MICE imputation + GridSearchCV + SMOTE + calibration
Depth selection10-fold CV searched max_depth ∈ {3,5,7,10} · chose depth=10, min_samples_leaf=3 (AUC 85.4%) · SMOTE inside each fold · 10-fold = 32 test samples per fold
BalancingSMOTE inside CV pipeline — 39 → 280 slipped per fold
Training set3.4 + 3.5 committed + FPDoR cycle snapshots · 319 features total
LabelShipped as planned vs. slipped
Class split280 shipped · 39 slipped → balanced 280/280
AUC-ROC (CV tuning)85.4% ± 9.5% (10-fold CV — more realistic with 3× more slipped examples)
Confidence caps🤖 real history → max 95% · ~🤖 no shipping history → max 85% minus FPDoR penalty
Why cap? Features with slip_count=0 cluster high. FPDoR penalty (0–15pts) restores differentiation: a feature at 9/17 FPDoR scores ~7pts lower than one at 16/17, even when both raw ML scores exceed 85.
High FPDoR = a feature has completed most or all of the 17-item FPDoR readiness checklist (Feature Planning Document of Record) — covering: PM ownership, RICE priority, acceptance criteria, docs plan, release type, cross-team deps, and more. 17/17 = fully ready. The higher the FPDoR, the stronger the signal the feature is well-defined and likely to ship.

🌳 Example Decision Tree (one of 200 trees, depth=10 — illustrative first 3 levels)
How a single tree scores a feature — example: 12/17 mandatory FPDoR · RICE 70 · Blocker · GA · slip_count=0
Is mandatory_pass_rate > 0.75? (mandatory FPDoR items — 19% importance)
└── Yes → Is slip_count > 0? (prior release slips — 21% importance)
└── No → Is jira_priority = Critical/High? (8% importance)
└── Yes → SHIP → this tree votes "will ship"
└── No   → SLIP → this tree votes "will slip"
└── Yes → SLIP → prior slips = strong signal even with good FPDoR
└── No   → Is fpdor_pass_rate > 0.60? (overall FPDoR — 9% importance)
└── Yes → SHIP → partial FPDoR still enough if mandatory items not the issue
└── No   → SLIP → low FPDoR overall = high risk
200 trees vote independently using the same 12 features with different random splits. Real trees go 10 levels deep — this shows the first 3 for clarity.
If 87 of 200 trees vote SHIP → raw confidence = 43.5% → displayed as 43% (Low).
