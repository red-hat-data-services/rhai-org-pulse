Component Heatmap

How to read the heatmap

  • Each row is a test component (e.g., Platform, Workbenches, Model Server).
  • Each column is a calendar date. Dates with no executions show "–".
  • Cell color indicates pass rate: 🟢 ≥95% · 🟡 80–94% · 🟠 60–79% · 🔴 <60%.
  • Cell content shows the pass percentage, plus pass/fail/skip counts below it.
  • Hover over a cell to see a dropdown with every individual Jenkins run (latest on top), each showing version, release, pass %, and a link to Jenkins.
  • Click a component name to navigate to its detail page with quality-gate heatmap, trend charts, and Jira analysis.

Execution Across Versions

Aggregated passed-test trends per version across all components. All release milestones (EA1 + EA2 + GA) within a version are combined.

How to use this chart

  • Version checkboxes — Toggle which RHOAI versions to show. Enables side-by-side comparison of quality across versions.
  • Each line represents total passed tests for a specific RHOAI version (e.g., "3.5", "3.6"), combining all release milestones (EA1 + EA2 + GA).
  • Upward trends indicate improving test coverage or stability. Sudden drops may signal regressions or infrastructure issues.
  • Compare versions side-by-side: newer versions should maintain or exceed the pass counts of older versions.

Version lifecycle glossary

  • EA1 (Early Access 1) — First pre-release validation milestone. Feature completeness ~70-80%.
  • EA2 (Early Access 2) — Second milestone, closer to GA. Feature completeness ~90%+.
  • GA (General Availability) — Production-ready release. All critical quality gates must pass.
  • Each version combines all milestones (EA1 + EA2 + GA) into one line for a holistic quality view of that version.
